# Каноническая сериализация JSON

Версия правил: `canonical_form_version: 1` (см. [`spec/version.yaml`](../spec/version.yaml)).

## Зачем это нужно

Conformance сравнивает не внутренние классы языков, а нормализованный JSON: поля,
идентификаторы перечислений, коды ошибок, порядок событий, решения о повторе. Значит
представление становится частью контракта, и «одинаковое поведение» шести SDK
определяется в том числе тем, как они сериализуют результат.

Второе применение - снимки мониторинга. Движок diff хэширует нормализованный снимок и
сравнивает с предыдущим. Если сериализация не канонична, хэш перестаёт быть
языконезависимым: перенос воркера с Python на TypeScript выдаст лавину ложных событий
об изменении цены по всему наблюдаемому рынку. Ущерб наносит не отсутствие данных, а
ложные события - для автоматики они неотличимы от настоящих.

Изменение этих правил - всегда MAJOR, даже если ни одна модель не менялась: оно
обнуляет сохранённые снимки, курсоры и ключи идемпотентности у всех пользователей.

## Правила

### Кодировка и структура

1. Кодировка UTF-8 без BOM.
2. Все строки нормализуются в форму **Unicode NFC** перед сериализацией.
3. Ключи объектов сортируются по возрастанию **кодовых точек Unicode**, не по алфавиту
   локали. Сортировка локали зависит от настроек машины и не воспроизводится.
4. Порядок элементов массива значим и не сортируется. Если порядок не важен по смыслу,
   он всё равно должен быть детерминированным - это ответственность схемы, а не
   сериализатора.
5. Никаких незначащих пробелов: без отступов, без пробела после `:` и `,`.
6. Экранирование минимальное: только то, что требует RFC 8259. Символы вне ASCII
   выводятся как есть, а не как `\uXXXX`.

### Числа

7. Целые числа выводятся без дробной части и без экспоненты.
8. Числа с плавающей точкой в каноническом JSON **запрещены**. Любая величина, для
   которой это естественно, выражается через `x-funora-type`.
9. `-0` запрещён, выводится `0`.

### Отсутствующие значения

10. Поле со значением `null` и отсутствующее поле - **разные вещи** и не
    взаимозаменяемы. `null` означает «наблюдалось и пусто», отсутствие - «не наблюдалось».
11. Необязательное поле, у которого нет значения, **опускается**, а не выводится как `null`.

Это различие принципиально для этого проекта: подстановка `null` вместо отсутствия
схлопывает «остатка нет» и «остаток не распарсился» в одно значение - ровно на том поле,
где ошибка стоит продавцу всего ассортимента.

### Типы предметной области

12. `money` - объект с ключами в каноническом порядке: `amount_minor`, `currency`, `scale`.
    Сумма всегда целая, в минорных единицах.
13. `instant` - строка RFC 3339 в UTC с суффиксом `Z` и ровно тремя знаками
    миллисекунд: `2026-08-18T04:12:33.000Z`. Смещения, отличные от `Z`, запрещены.
14. `duration` - целое число миллисекунд.
15. `entity_id` и `cursor` - строки, выводятся как есть, без нормализации регистра.

## Что этим проверяется

Обязательный вектор conformance `money/canonical` содержит значения, на которых
реализации расходятся первыми:

| Вход | Ожидаемый канонический вывод |
|---|---|
| 1234.10 RUB | `{"amount_minor":123410,"currency":"RUB","scale":2}` |
| 0.10 RUB | `{"amount_minor":10,"currency":"RUB","scale":2}` |
| 0.1 + 0.2 RUB | `{"amount_minor":30,"currency":"RUB","scale":2}` |
| −0.00 RUB | `{"amount_minor":0,"currency":"RUB","scale":2}` |
| 9007199254740993 (id) | `"9007199254740993"` - строка, не число |

Последняя строка не декоративная: это первое целое, которое `Number` в JavaScript
не может представить точно. Идентификатор, распарсенный в число, тихо превращается
в соседнее значение.

Отдельный обязательный вектор прогоняет одну и ту же фикстуру дважды - под `TZ=UTC` и
под `TZ=Asia/Yekaterinburg` при замороженном `observed_at` - и требует побайтово
идентичный результат.
